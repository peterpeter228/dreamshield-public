# DreamShield interface design
Concept: concept.png, generated using built-in Image Gen before implementation. Whole-screen compact tool, cool white #f7f9fb, white panels, ink #121d2b, teal #17685f, semantic amber gaps. System UI typography 36/17/13/11px, 8px panel radius, 1px borders. Original 1.7px outline SVG icons are code-native. Desktop 1.7:1 content/repair grid; mobile single column. No image assets are required at runtime.

Allowed core copy: DreamShield; Protection desk; Check and repair native perps protection; Tokyo testnet · 50383; Replay · fixtures; Owner; Recheck; Position and protection; Prepare stop-loss; Preview stop; Native stops; Evidence details; Operation timeline; Configuration verification is not execution assurance.

Intentional functional corrections to generated concept: no fabricated timestamp/block; no ETH branding asset; no custom sizing control (P0 whole-at-trigger only); no statement promising 100% execution; fixture disclaimer explicit; connected wallet kept separate from displayed owner. Scenario control moved above account rail for discoverability. No green network dot implying connection. Native atomic values are formatted without floats.

Components: App composition / fetching / wallet identity; Protection read-only evidence; Repair validated unsigned preview; Timeline operation read-back; ui primitives. No public signing implementation. Errors revoke verification, freshness is recomputed each second, owner identity change clears connection. Browser QA scope and screenshot observations are recorded separately in the [historical responsive QA](../../../tests/browser/RESPONSIVE_QA.md) and [Phase1 desktop replay evidence](../../../evidence/phase1-2026-10-26/NOTES.md). Those records retain their historical viewport and replay-only limits; this documentation update adds no UI, mobile, wallet or live acceptance.

Owner integration addition: explicit local-owner-only reserve + native-wallet review controls, selected pending reduce-only stop cancellation, persisted unresolved operation reconciliation. The SDK is lazy-loaded only after an owner action; Vite emits a 1.43MB protocol chunk warning, while initial application JS is ~251KB. No signing request was executed during implementation. Wallet preflight is delegated to protocol helper and must retain exact account/chain/expiry checks.
